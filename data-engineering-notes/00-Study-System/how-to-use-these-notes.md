# How to Use These Notes

## 1. Why These Notes Exist

These notes are here to help me:

- Remember concepts I have already learned.
- Understand topics in simple words.
- Revise quickly before interviews.
- Prepare for Data Engineer interviews.
- Identify topics I need to practice again.

**Important:** I do not need to memorize every line. I need to understand the main idea, remember when to use it, and explain it in my own words.

---

## 2. How to Write Notes

Whenever I learn a new topic, I should write short and useful notes.

For each topic, answer these questions:

1. **What is it?** Explain it in simple words.
2. **Why do we need it?** What problem does it solve?
3. **How does it work?** Explain the basic working process.
4. **When should I use it?** Give a practical situation.
5. **What are its limitations?** When might it not be a good choice?
6. **What can an interviewer ask?** Write a few important questions.

### Rules for Writing

- Use simple English.
- Write in my own words.
- Prefer short sentences and bullet points.
- Add code only when it helps me understand or practice.
- Avoid copying long explanations from courses or websites.
- Keep important differences and common mistakes.
- If I cannot explain something simply, I need to study it again.

**My target:** A topic should be easy to revise in 2–5 minutes whenever possible.

---

## 3. How to Study a New Topic

Follow these steps whenever I learn something new.

### Step 1: Understand

Read or watch the explanation and understand the main idea.

Do not try to memorize everything immediately.

### Step 2: Close the Learning Material

Close the video, website, or course notes.

Try to explain the topic without looking at anything.

### Step 3: Write from Memory

Write the important points in my own words.

If I forget something, check the learning material and correct my notes.

### Step 4: Practice

Solve a question, write some code, or work through a practical example.

For Data Engineering topics, practice whenever possible using SQL, Python, PySpark, or Databricks.

### Step 5: Test Myself

Ask myself:

- Can I explain this topic without reading?
- Can I solve a basic question about it?
- Do I know when to use it?
- Can I explain its limitations?

If the answer is no, revise that topic again.

---

## 4. How to Revise and Remember

Reading the same notes repeatedly is not enough. I should try to remember the answer before looking at the notes.

Use this revision schedule as a starting point:

| When | What to do |
|---|---|
| Same day | Review the topic after learning it. |
| Next day | Recall the main points without looking. |
| After 3 days | Test myself again. |
| After 7 days | Solve a question or explain the topic. |
| After 14 days | Check whether I still remember it. |
| Before an interview | Review the important points and weak topics. |

If I forget a topic, that is not a failure. It tells me what I need to revise.

I can adjust the schedule depending on how well I remember the topic.

## 6. How to Prepare One Day Before an Interview

**Do not try to learn the entire syllabus in one day.** Focus on remembering what I already know and fixing the most important gaps.

### First: Review Quick Revision Notes

Open the files inside `15-Quick-Revision/`.

Review short explanations, important differences, common mistakes, and key points.

### Second: Review Important Technical Topics

Prioritize topics that are important for the role and that I have already studied.

For a Data Engineer interview, this may include:

- SQL joins, aggregations, window functions, and query problems.
- Python fundamentals and basic coding problems.
- PySpark transformations, joins, partitions, and performance.
- Databricks and Delta Lake fundamentals.
- ETL pipelines and data modeling.
- My project design, decisions, and challenges.

Use the job description to decide which topics deserve the most attention.

### Third: Practice Explaining Answers

Choose important questions and answer them aloud without reading.

For every answer, try to explain:

1. What it is.
2. Why it is needed.
3. How it works.
4. When it is useful.
5. Any important limitation.

### Fourth: Review My Projects

Be ready to explain:

- What problem the project solves.
- Where the data comes from.
- How the data is processed.
- Which tools I used and why.
- How I handle errors and bad data.
- How I would improve the project.

Only claim experience or work that I can explain honestly.

### Fifth: Review My Mistakes

Open `16-Errors-and-Lessons/`.

Review questions I previously answered incorrectly, concepts I forgot, and problems I found difficult.

### Final Rule

Get enough sleep. A tired mind may struggle to recall even familiar topics.

---

## 7. How to Mark My Progress

Use these labels in my notes or revision tracker:

- **Not Started:** I have not learned this topic.
- **Learning:** I am still understanding it.
- **Needs Revision:** I understood it before but cannot explain it confidently now.
- **Practicing:** I understand it but need more problem-solving practice.
- **Interview Ready:** I can explain it clearly and answer common questions.

Mark a topic as **Interview Ready** only when I can explain it without reading and handle a practical question about it.

---

## 8. My Daily Study Routine

Even on a busy working day, I should aim for a small amount of consistent practice.

A simple routine:

- **10 minutes:** Revise an older topic.
- **30–45 minutes:** Learn or practice one main topic.
- **15–20 minutes:** Solve a question or write code.
- **5 minutes:** Record what I learned and what I need to revisit.

If I have less time, I can shorten the session instead of skipping it completely.

Consistency is more important than making perfect notes.

---

## 9. Rules I Must Remember

1. Understanding a topic once does not mean I will remember it forever.
2. I should test my memory instead of only rereading.
3. I should practice coding, not just read solutions.
4. I should keep notes short, clear, and useful.
5. I should revisit topics that I forget.
6. I should prioritize topics based on my target job descriptions.
7. I should understand my projects deeply rather than collect many unfinished projects.
8. I should not learn every tool just because it appears in a roadmap.
9. I should explain concepts in my own words.
10. I should measure progress by what I can explain and solve, not by how many videos I finish.

---

## My Main Goal

**Learn → Understand → Practice → Recall → Revise → Explain.**

I am building these notes to make my knowledge easier to remember and use.

When an interview is near, I should not need to study every topic from the beginning. I should be able to open these notes, review the important points, test myself, and identify the few areas that need more attention.
